Firme API finali (per LOD-02..05):

```ts
// src/app/camera.ts (invariata)
export type LodTier = "near" | "medium" | "far"
export function lodForZoom(level: ZoomLevel): LodTier  // ora politica LOD-01 dichiarata

// src/render/lod-profile.ts (nuovo)
export type RoadDetailLevel = "body" | "casing" | "marking"
export interface LodPresentationProfile {
  readonly facadeStrength: number    // moltiplicatore altezza facade: 0 = nascosta, 1 = baseline
  readonly roadDetail: RoadDetailLevel
  readonly labelMinPriority: number  // soglia priorita' label: 0 = tutte
  readonly cullMinAreaPx2: number    // soglia culling in px^2: 0 = culling disattivato
}
export const LOD_TIERS: readonly LodTier[]                                     // ["far","medium","near"]
export const LOD_PROFILES: Readonly<Record<LodTier, LodPresentationProfile>>  // congelato, un'istanza per tier
export function lodProfileForTier(tier: LodTier): LodPresentationProfile
export function lodProfileForZoom(level: ZoomLevel): LodPresentationProfile    // clamp -> lodForZoom -> profilo
```

Valori iniziali (far / medium / near):

| Parametro | far | medium | near |
| --- | --- | --- | --- |
| facadeStrength | 0 | 0.6 | 1 |
| roadDetail | body | casing | marking |
| labelMinPriority | 100 | 75 | 0 |
| cullMinAreaPx2 | 64 | 16 | 0 |

Provenienza dei valori (tutti parametrici, nessuna logica nel renderer):

- facade: scala del design `[0, 0.25, 0.6, 0.85, 1]` letta ai livelli
  rappresentativi 0/2/4, coerente con F-LOD-2 (FAR facade ~0, NEAR piena);
- roadDetail: ladder FAR body / MEDIUM casing / NEAR marking del design;
- labelMinPriority: soglie sulla scala di priorita' reale del compiler
  (`src/world/compiler/compiled.ts`: road 10..100, place 105/110), quindi FAR
  tiene solo motorway (100) e luoghi maggiori (105/110), MEDIUM tiene da
  tertiary (75) in su, NEAR tutte;
- cullMinAreaPx2: px² alla scala di vista corrente, crescente verso lo zoom out,
  0 = nessun culling (NEAR resta identico alla baseline per LOD-03/04).

Ownership: nessuno stato mutabile; `LOD_PROFILES` e le voci sono `Object.freeze`
e condivisi per riferimento, quindi i consumatori non copiano ne' mutano i
parametri. Nessun codice errore nuovo, nessuna risorsa da liberare.

## Handoff

LOD-02 (label), LOD-03 (facade), LOD-04 (road detail) e LOD-05 (culling)
consumano il profilo con `lodProfileForTier(lodForZoom(level))`, oppure
direttamente `lodProfileForZoom(level)`: una sola risoluzione, nessuna seconda
tabella tier->livello e nessuna soglia duplicata nel renderer. Il renderer non
e' ancora toccato, quindi il profilo non ha effetti a runtime finche' LOD-02..05
non lo leggono (SOLID-04 e' indipendente).

Scostamenti e punti aperti da conoscere:

- la scheda LOD-03 cita la scala facade a 5 valori (`FAR ~0, MEDIUM_FAR 0.25,
  DEFAULT 0.6, MEDIUM_NEAR 0.85, NEAR 1`); il profilo LOD-01 e' per tier e usa le
  ancore 0 / 0.6 / 1 dei livelli rappresentativi 0/2/4, come richiesto da
  F-LOD-2 e dalla scheda LOD-01 ("profilo per tier"). Se serve granularita' per
  livello, la scala a 5 valori va aggiunta una volta sola dentro il profilo, non
  nel renderer;
- le soglie label sono agganciate ai valori numerici di priorita' del compiler
  (10..110): se il compiler cambia scala, il profilo va riallineato;
- i px² di culling sono sperimentali e vanno misurati con i benchmark
  (ZOOM-05 per i fattori, CITY-02 per il costo per metro quadro per tier);
- `lodForZoom` e' totale e clampato, quindi anche i chiamanti non tipizzati non
  possono uscire dai 5 livelli. Debito residuo: nessuno.
