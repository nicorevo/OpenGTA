## Risultato

Nuovo modulo puro `src/app/camera.ts` con i livelli discreti di zoom, i fattori
sperimentali e i bounds camera in metri canonici. Nessuna dipendenza runtime:
il solo import e' `import type` da `src/world/model/types.ts` (`Vec2`,
`Bounds2D`), quindi il modulo non trascina Pixi, Rapier o DOM e resta
consumabile in Vitest puro. I limiti dichiarati:

- i fattori di `ZOOM_STEPS` sono sperimentali e verranno fissati dai benchmark
  di ZOOM-05;
- `lodForZoom` e' un placeholder (0-1 far, 2 medium, 3-4 near) che LOD-01
  sostituira' con il profilo reale;
- centro camera = posizione ricevuta: il modulo non decide come il chiamante
  aggiorni la posizione (ZOOM-02/04);
- `cameraBounds` rifiuta scale non positive o non finite: `selectActiveChunks`
  richiede bounds finiti e crescenti, quindi una scala degenere fallisce subito
  invece di propagare bounds non validi nella firma di streaming.

Firme API finali (per ZOOM-02):

```ts
export type ZoomLevel = 0 | 1 | 2 | 3 | 4
export const ZOOM_STEPS: readonly [0.7, 0.85, 1.0, 1.2, 1.45]
export type LodTier = "near" | "medium" | "far"
export interface ScreenSize { readonly width: number; readonly height: number }
export function clampZoom(level: number): ZoomLevel
export function zoomFactor(level: ZoomLevel): number
export function lodForZoom(level: ZoomLevel): LodTier
export function cameraBounds(position: Vec2, screenSize: ScreenSize, scale: number): Bounds2D
```

Contratto dei comportamenti:

- `clampZoom`: arrotonda all'intero piu' vicino e satura a 0..4; input non
  finito (NaN, +/-Infinity) -> livello di default 2 (centro).
- `zoomFactor`: `ZOOM_STEPS` indicizzato sul livello clampato; e' 1 al livello
  di default e strettamente crescente; per ZOOM-02 `viewScale = baseScale *
  zoomFactor(level)`.
- `lodForZoom`: mappa placeholder 0-1 -> far, 2 -> medium, 3-4 -> near.
- `cameraBounds`: `halfWidth = screenSize.width / scale / 2`,
  `halfHeight = screenSize.height / scale / 2`, bounds centrati su `position`
  (stessa semantica di `PixiRenderer.cameraBounds()`); lancia
  `Error("camera scale must be a positive finite number")` se `scale` non e'
  finita o <= 0.
- Ownership: nessuno stato mutabile, nessuna allocazione condivisa, nessun
  codice errore oltre all'eccezione su scala invalida; non serve `dispose`.
